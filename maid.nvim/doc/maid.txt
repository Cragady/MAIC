1. INTRODUCTION                                                 *maid-intro*

maid.nvim makes nvim MAID's interface: the conversation and the input are
nvim buffers and MAID's engine runs as their job (|maid-interface|). It can
also run MAID's own TUI in a terminal (|:MaidTerminal|). Either way it sends
buffers, selections, diagnostics and the quickfix list into MAID's input;
nothing is sent to the model until you send it.

MAID, running inside nvim, connects back to this nvim and uses it as its
editor: files and diffs open here, the theme follows your colorscheme, and
User autocmds fire (|maid-events|). See |maid-host| and docs/nvim.md in the
MAID repository.

Needs nvim 0.10 or later and `maid` on $PATH (or |maid-cmd|).

==============================================================================
2. SETUP                                                        *maid-setup*

lazy.nvim, from the MAID checkout: >lua
    { dir = "~/dev2/MAID/maid.nvim", opts = {} }
<
As a package: >lua
    vim.cmd.packadd("maid.nvim")
    require("maid").setup({})
<
`plugin/maid.lua` only defines the commands. Keymaps are set by
|maid.setup()|; without it there are none.

                                                                *maid.setup()*
require("maid").setup({opts})
    Merges {opts} over |maid-defaults| and sets the keymaps
    (|maid-keymaps|) unless `keymaps = false`. May be called again: options
    not given return to their defaults, and the keys the last call set are
    removed before the new ones are set.

3. THE INTERFACE                                            *maid-interface*

|:Maid| opens it (with `ui = "nvim"`, the default; |maid-ui|), and
`maid --ui nvim` from the shell starts nvim with it. maid.nvim starts the
engine, `maid --rpc` (|maid-cmd|, |maid-args| and :Maid's arguments), as
this tab's job and speaks MAID's engine protocol to it over its stdin and
stdout. One interface per tab.

                                                 *maid-conversation* *ft-maid*
The conversation is a buffer of filetype `maid`, highlighted as markdown,
that only maid.nvim writes: `❯` your messages, the replies as they stream,
`⏺` each tool call with its output indented under it, `↯` each steering
action, notices, and `▣ model · time · tool calls` after each turn. A tool's
output of |maid-fold_output| lines or more and the model's reasoning are
folded closed once done; |za| and your own fold keys open them. The winbar
shows the title, model, mode and what MAID is doing. A window whose cursor is
on the last line follows the stream.

                                                 *maid-input* *ft-maid-input*
The input is a buffer of filetype `maid-input` under it, an ordinary buffer
for your motions, mappings and plugins. <CR> in normal mode or <M-CR> in
insert mode sends it. `/cmd` runs a MAID command (`/mode plan`, `/model
qwen-9b`), `//text` sends text starting with one slash, `!cmd` runs a shell
command. While a turn runs, what you send goes to it at its next step.

                                                               *maid-floats*
An approval opens a float over the conversation: `y` yes, `n` or <Esc> no,
`N` no with a reason, `a` always, `t` trip the harness, `e` open the file,
`d` (a write) the proposed content against the file as a diff in a new tab,
<C-c> no and cancel the turn. A question lists its options: a digit picks
one, <CR> types an answer, <Esc> gives none. |:Maid| focuses a waiting one.

                                                             *maid-steering*
<C-c> cancels the turn (or stops a running `!cmd`). <C-s> pauses it and
opens the pause menu: <C-q> resumes, `s` steer, `d` drop, `f` further,
`k` keep, `h` halt; what is in the input goes with `s`, `d` and `f` as their
note. <Esc> closes the menu to type a message, which resumes the turn when
sent. <C-q> resumes from either buffer, and |:MaidSteer| does any of them.
The keys are |maid-buffer_keymaps|.

                                                              *maid-history*
A resumed session shows its last three exchanges, and a reply or a command
still running as it goes on. While earlier history is left, the first line
says so: moving the cursor there, or |:MaidOlder|, loads the ten exchanges
before what is shown, above it.

                                                             *maid-sessions*
A tab's engine holds every session opened in it, each with a conversation
buffer of its own under the tab's one input. |:MaidNew|, |:MaidSwitch|,
|:MaidFork|, |:MaidBg|, |:MaidPark| and |:MaidStop| move between them; the
session left becomes what `leave.switch` in MAID's settings says (by
default a working one goes to the background, and is parked once its work
ends, and an idle one is parked), unless --bg, --park or --stop says
otherwise; a case set to "ask" asks with |vim.ui.select()|. Quitting nvim
ends the tab's engine as MAID's `:q` does (`leave.quit`, "ask" asking with
|vim.ui.select()| before nvim goes). A background
session keeps writing its buffer; its approvals and
questions wait until you switch to it, with one notification naming it. The
winbar counts the other sessions. A parked or stopped session's buffer goes
once no window shows it.

maid.nvim fires the |maid-events| itself and runs |:checktime| after MAID
writes a file. Closing nvim ends the engine, which parks its sessions.

==============================================================================
4. COMMANDS                                                  *maid-commands*

                                                                       *:Maid*
:Maid [args]
    Opens MAID in the configured layout (|maid-open|), or focuses the one
    this tab already has, showing its windows again if they were hidden:
    the interface (|maid-interface|), or MAID's TUI in a terminal with
    `ui = "terminal"` or arguments only the TUI takes (`-p`, `-i`, `-c`,
    `-r`, `--context`, `--image`, `--fork-at`, `--bare`, a prompt). One MAID
    per tab, reused. [args] are added to the command line when MAID starts,
    after |maid-args|: >vim
        :Maid --model qwen-9b
        :Maid -c
<    With `open = "tab"` MAID has a tab of its own and :Maid goes there.

                                                               *:MaidTerminal*
:MaidTerminal [args]
    MAID's own TUI in a terminal, as |:Maid| with `ui = "terminal"`.

                                                                    *:MaidNew*
:MaidNew [--bg|--park|--stop] [DIR]
    Another session in this tab's engine, in focus; with DIR, `/cd DIR`
    follows. See |maid-sessions|.

                                                                 *:MaidSwitch*
:MaidSwitch [--bg|--park|--stop] [ID|TITLE]
    Goes to another session: a loaded one, a parked one (resumed), or any
    transcript by id. Alone, the switcher (|vim.ui.select()|): a new session
    first, then every other with what it is doing, its model and workspace.

                                                                   *:MaidFork*
:MaidFork [--bg|--park|--stop]
    Forks this session into a second one and goes to it.

                                                                     *:MaidBg*
:MaidBg
    Sends this session to the background, where it keeps working, and opens
    the switcher to pick where to go.

                                                          *:MaidPark* *:MaidStop*
:MaidPark [ID]
:MaidStop [ID]
    Ends this session (through the switcher, to pick where to go) or session
    ID: park for now (it resumes where it was), stop for good (it stays a
    transcript). A working one is asked about first.

                                                                  *:MaidOlder*
:MaidOlder
    Loads the conversation's ten exchanges before the oldest one shown,
    above it. See |maid-history|.

                                                                  *:MaidSteer*
:MaidSteer {action} [note]
    Steers the interface's running or paused turn: `steer`, `drop` and
    `further` (with [note], else what is in the input), `interrupt`
    (pauses), `keep`, `halt`. See |maid-steering|.

                                                                 *:MaidToggle*
:MaidToggle
    Hides this tab's MAID windows (MAID keeps running) or shows them again.
    Starts MAID when there is none.

                                                                   *:MaidSend*
:[range]MaidSend
    With a range, those lines as a fenced snippet headed with the path and
    the line numbers: >
        `src/agent.cpp` lines 120-124:
        ```cpp
        ...
        ```
<    The fence is longer than any run of backticks inside. Without a range,
    the buffer's path in backticks, for the agent to read itself. In visual
    mode the selection is the range; `:%MaidSend` sends the whole buffer.

    When MAID is connected to this nvim the text goes over its channel
    (`rpcnotify(chan, "maid_send", text)`). When it is not, it is typed into
    this tab's MAID terminal as a bracketed paste (ESC [200~ ... ESC [201~),
    which MAID takes into its input whole, in any mode. Either way it is not
    sent to the model.

                                                            *:MaidDiagnostics*
:MaidDiagnostics[!]
    This buffer's diagnostics (|vim.diagnostic.get()|), one line each: >
        src/a.c:12:5: error: expected ';' [clangd]
<    With [!], every buffer's.

                                                              *:MaidInterrupt*
:MaidInterrupt
    Stops MAID's running turn as its first Ctrl-C does, from any window. In
    the interface it cancels the turn (or a running `!cmd`). When MAID is
    connected it goes over its channel
    (`rpcnotify(chan, "maid_interrupt")`): a running turn, `!` command or
    pending approval is stopped, and an idle MAID only says so (your draft
    stays). Without a connection, Ctrl-C is typed into this tab's MAID
    terminal.

                                                               *:MaidQuickfix*
:MaidQuickfix
    The quickfix list, `path:line:col: type: text` per item; an item with no
    location is its text alone. The list's title heads it.

5. OPTIONS                                                    *maid-options*

                                                               *maid-defaults*
Every option lives in one table, `require("maid").defaults`. |maid.setup()|
deep-merges your {opts} over it (`vim.tbl_deep_extend("force", ...)`),
which is what lazy.nvim's `opts` passes, so you name only what you change: >lua
    require("maid").setup({ open = "float", keymaps = { quickfix = false } })
<
The table, as shipped: >lua
    {
      cmd = "maid",
      args = {},
      ui = "nvim",
      open = "vsplit",
      size = nil,
      prefix = "<leader>m",
      keymaps = {
        open = "<leader>mm",
        toggle = "<leader>mt",
        send = "<leader>ms",
        send_selection = "<leader>ms",
        send_buffer = "<leader>mb",
        diagnostics = "<leader>md",
        workspace_diagnostics = "<leader>mD",
        quickfix = "<leader>mq",
        interrupt = "<leader>mc",
      },
      buffer_keymaps = { interrupt = "<C-c>", pause = "<C-s>", resume = "<C-q>",
                         send = "<CR>", send_insert = "<M-CR>" },
      input_height = 6,
      fold_output = 4,
      terminal_escape = "<C-\\><C-n>",
      terminal_passthrough = { ["<Esc>"] = true, ["<C-c>"] = true },
      filetypes = { conversation = "maid", terminal = "maid", input = "maid-input" },
    }
<
Read it from Lua to build on it, never to change it: >lua
    print(vim.inspect(require("maid").defaults.keymaps))
<
                                                                    *maid-cmd*
cmd         The program: a name on PATH, a path, or a list of the program
            and its arguments (`{ "maid", "--harness", "dumb" }`).

                                                                   *maid-args*
args        Arguments for every start, before those given to |:Maid|.

                                                                     *maid-ui*
ui          "nvim": |:Maid| opens the interface (|maid-interface|).
            "terminal": MAID's own TUI in a terminal.

                                                                   *maid-open*
open        Where MAID opens: "split" (below), "vsplit" (right), "float"
            (centred, rounded border) or "tab" (a tab of its own).

                                                                   *maid-size*
size        "split": rows (default 15). "vsplit": columns (default 40% of
            the screen). "float": a fraction of the editor (default 0.8).

                                                                 *maid-prefix*
prefix      Where the default keymaps live: a default key that starts with
            `<leader>m` moves under it. Keys you name in `keymaps` stay
            exactly as you give them.

                                                           *maid-keymaps-opt*
keymaps     A table of name = key (|maid-keymaps|); merged over the
            defaults, so a table moves or drops single ones by name. false:
            none. true: the defaults. >lua
                keymaps = { send = "<leader>ss", quickfix = false }
<
                                                         *maid-input_height*
input_height
            The interface's input: rows under the conversation.

                                                          *maid-fold_output*
fold_output
            A tool's output of at least this many lines is folded closed in
            the conversation once it is done. false: never.

                                                        *maid-terminal_escape*
terminal_escape
            The key that leaves terminal mode in MAID's terminal. The
            default is nvim's own |t_CTRL-\_CTRL-N|, which needs no mapping;
            any other key is mapped buffer-local there. See |maid-esc|.

                                                   *maid-terminal_passthrough*
terminal_passthrough
            Keys that reach MAID in its terminal even when a global
            terminal-mode mapping holds them: `key = true`, `false` drops one.
            Each is a buffer-local, |:map-nowait| |:tnoremap| of the key to
            itself in MAID's terminal only. >lua
                terminal_passthrough = { ["<C-w>"] = true }
<
                                                         *maid-filetypes*
filetypes   MAID's buffers get these filetypes so plugins can include or
            exclude them: `conversation` and `input` (the interface's
            buffers) and `terminal` (MAID's terminal, set before the job
            starts, so a |TermOpen| autocmd sees it).

6. KEYMAPS                                                    *maid-keymaps*

Set by |maid.setup()|; the name is the key in the `keymaps` table.

    name                    keys          mode     does ~
    open                    <leader>mm    normal   |:Maid|
    toggle                  <leader>mt    normal   |:MaidToggle|
    send                    <leader>ms    normal   |:MaidSend| (the path)
    send_selection          <leader>ms    visual   :'<,'>MaidSend
    send_buffer             <leader>mb    normal   :%MaidSend
    diagnostics             <leader>md    normal   |:MaidDiagnostics|
    workspace_diagnostics   <leader>mD    normal   :MaidDiagnostics!
    quickfix                <leader>mq    normal   |:MaidQuickfix|
    interrupt               <leader>mc    normal   |:MaidInterrupt|

                                                      *maid-buffer_keymaps*
In MAID's own buffers only, buffer-local (`buffer_keymaps`, same names):

    name          keys      mode           where              does ~
    interrupt     <C-c>     normal         every MAID buffer  |:MaidInterrupt|
    pause         <C-s>     normal, insert conversation, input  pauses the turn
    resume        <C-q>     normal, insert conversation, input  resumes it
    send          <CR>      normal         input              sends the input
    send_insert   <M-CR>    insert         input              sends the input

(insert mode for pause and resume in the input only)

and <C-c> in terminal mode is passed through to MAID, whose own Ctrl-C
interrupts (|maid-terminal_passthrough|). <C-c> is never mapped globally.

                                                                   *maid-esc*
In MAID's terminal, <Esc> goes to MAID, whose input is vim-like and needs it
for normal mode, even when you have the common >vim
    tnoremap <Esc> <C-\><C-n>
<a global mapping that makes <Esc> leave terminal mode. maid.nvim maps <Esc>
to itself buffer-local in MAID's terminal (|maid-terminal_passthrough|), so
your mapping keeps working in every other terminal. To leave terminal mode in
MAID's, press <C-\><C-n>, or set |maid-terminal_escape| to a key of your
own. A |TermOpen| autocmd that maps keys in every terminal can skip MAID's: >lua
    if vim.bo[ev.buf].filetype == "maid" then return end
<
                                                       *maid-never-overwrite*
maid.nvim never overwrites a mapping. Before it sets a default key it asks
|maparg()| and |mapcheck()| for that mode: when another mapping holds the key,
or shares a prefix with it (so one of the two would wait 'timeoutlen'), the
key is skipped. Every skipped key is reported once per session in one
|vim.notify()| warning, naming the key, the mode and what holds it: the
mapping's description or right-hand side and the script and line that set
it. Mappings made from Lua name their file only when nvim runs with -V1;
otherwise the warning says "Lua". >
    maid.nvim never overwrites a mapping:
      <leader>mq (normal) skipped, held by "Quickfix list" from ~/.config/nvim/lua/keys.lua:12
<
A key you name in `keymaps` is set even when something holds it, since you
chose it, and is reported the same way as shadowing what held it. The keys
maid.nvim sets in its own buffers are buffer-local and never touch your
global mappings. |:checkhealth| maid lists every key.

                                                    *maid-health* *maid-check*
:checkhealth maid
    Lists every key maid.nvim sets (global, and buffer-local in MAID's own
    buffers), the keys MAID's own input needs in its terminal (<Esc>,
    <C-w>, <C-p>, <S-Tab>, <C-z>, <C-c>, <M-CR>) and, when llama.vim is
    installed (`g:llama_config` is set or its autoload/llama.vim is on
    'runtimepath'), every key llama.vim uses, against your mappings in the
    modes each is used in. Your buffer-local mappings are collected too: the
    check opens a plain file buffer, scratch buffers of filetypes
    `maid-input` and `maid` and a terminal of filetype `maid` in a tab of its
    own, reads
    what your FileType, BufEnter and TermOpen autocmds mapped there, and
    closes them again.

    Each key is one line: OK when it is free (or a passthrough makes it
    reach MAID), WARN when maid.nvim skipped it, a key you named shadows
    something, two mappings share a prefix so one waits 'timeoutlen', or an
    insert-mode key starts with a key that types (with a <Space> leader,
    llama.vim's default insert-mode <leader>llf makes every typed space
    wait), and ERROR when a key MAID needs never reaches it in its terminal.
    Every WARN and ERROR comes with the fix. `maid nvim keymaps` runs the
    same check outside nvim, against your config.

7. EVENTS                                                      *maid-events*

A connected MAID fires |User| autocmds in this nvim with
|nvim_exec_autocmds()|, and the interface fires the same ones as it shows
the engine's events. Every `data` has `session`, MAID's session id; the rest
as applies:

                                                               *MaidTurnStart*
MaidTurnStart       A turn starts. `model`.
                                                                *MaidToolCall*
MaidToolCall        The model calls a tool. `tool`, `path` (absolute, "" for
                    none), `summary`.
                                                                *MaidApproval*
MaidApproval        MAID asks you to approve something, with `verdict` =
                    "pending"; then again with your answer, `verdict` =
                    "yes", "no", "always" or "trip". `tool`, `path`,
                    `summary`, `reason`.
                                                             *MaidFileWritten*
MaidFileWritten     A tool changed a file (a write, an edit, a patch, a
                    move's two ends, a delete). `tool`, `path`.
                                                                 *MaidTurnEnd*
MaidTurnEnd         The turn is over. `model`, `tool_calls`, `seconds`,
                    `interrupted`.

Example: >lua
    vim.api.nvim_create_autocmd("User", {
      pattern = "MaidApproval",
      callback = function(ev)
        if ev.data.verdict == "pending" then
          vim.notify("MAID asks: " .. ev.data.summary, vim.log.levels.WARN)
        end
      end,
    })
    vim.api.nvim_create_autocmd("User", {
      pattern = "MaidFileWritten",
      callback = function(ev) print("MAID wrote " .. ev.data.path) end,
    })
<
MAID also runs |:checktime| after it changes a file, so an open buffer
reloads (or asks, when it has unsaved changes).

8. LUA                                                            *maid-lua*

require("maid") has, besides |maid.setup()|:

open({args})                                                  *maid.open()*
    |:Maid| with a list of arguments.

toggle()                                                    *maid.toggle()*
    |:MaidToggle|.

interrupt()                                              *maid.interrupt()*
    |:MaidInterrupt|. Returns "engine" (the interface), "rpc", "key"
    (Ctrl-C into the terminal) or nil (no MAID here).

send_text({text})                                        *maid.send_text()*
    Puts {text} into MAID's input, never sent. Returns "input" (the
    interface's input buffer), "rpc" (over MAID's channel), "paste" (into
    this tab's terminal) or nil (no MAID here).

command({line})                                            *maid.command()*
    Runs a command line in MAID as if typed: >lua
        require("maid").command(":mode plan")
<    In the interface it goes to the engine. Returns false when no MAID is
    connected.

require("maid.ui").state()                                    *maid.ui.state()*
    This tab's interface as plain values, for a statusline: `session`,
    `response` (nil when idle), `paused`, `activity`, `mode`, `model`,
    `conversation` and `input` (buffers), `float`. nil without one.

channel()                                                  *maid.channel()*
    MAID's channel: the client named "maid" whose pid is this tab's
    terminal job; with no MAID terminal in the tab, the newest "maid"
    client. nil when MAID is not connected.

format_snippet({path}, {first}, {last}, {lines}, {filetype})
format_diagnostics({items})
format_quickfix({items})
    The formatters behind the commands, for your own mappings.

9. MAID'S SIDE                                                   *maid-host*

nvim sets $NVIM to its socket for every job. MAID connects to it as a
msgpack-rpc client named "maid" only when it is a Unix socket owned by you
and the nvim behind it (SO_PEERCRED) runs as you and is one of MAID's parent
processes; anything else is refused, and the first line in MAID says why.
MAID's status strip shows `nvim` while connected; `:nvim` in MAID says more.

Connected:
- `:e FILE` and `e` at an approval prompt open the file here with |:drop|,
  in the window you edit in (not MAID's terminal).
- `d` at an approval prompt for a write opens a new tab with the file
  against a read-only scratch buffer holding the proposed content, both in
  |diff-mode|.
- MAID's theme follows your colorscheme live, read with |nvim_get_hl()|
  after every |ColorScheme| (`follow_nvim_theme` in MAID's settings).
- MAID's own Lua gets `maid.nvim.exec`, `buffers`, `diagnostics` and
  `current`, which run here.
- The model gets a `diagnostics` tool, judged as a read like any read. It
  can never run Lua here or change a buffer: its edits are file writes
  through MAID's harness, which this nvim then reloads.
- |:MaidInterrupt| reaches it as `maid_interrupt`.

`maid --bare` (or `MAID_BARE=1`) never connects, even inside nvim: then
|:MaidSend| falls back to the bracketed paste and |:MaidInterrupt| to
typing Ctrl-C. MAID's status strip shows `bare`; `:h bare` in MAID.
