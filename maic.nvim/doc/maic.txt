1. INTRODUCTION                                                 *maic-intro*

maic.nvim makes nvim MAIC's interface: the conversation and the input are
nvim buffers and MAIC's engine runs as their job (|maic-interface|). It can
also run MAIC's own TUI in a terminal (|:MaicTerminal|). Either way it sends
buffers, selections, diagnostics and the quickfix list into MAIC's input;
nothing is sent to the model until you send it.

MAIC, running inside nvim, connects back to this nvim and uses it as its
editor: files and diffs open here, the theme follows your colorscheme, and
User autocmds fire (|maic-events|). See |maic-host| and docs/nvim.md in the
MAIC repository.

Needs nvim 0.10 or later and `maic` on $PATH (or |maic-cmd|).

==============================================================================
2. SETUP                                                        *maic-setup*

lazy.nvim, from the MAIC checkout: >lua
    { dir = "~/dev2/MAIC/maic.nvim", opts = {} }
<
As a package: >lua
    vim.cmd.packadd("maic.nvim")
    require("maic").setup({})
<
`plugin/maic.lua` only defines the commands. Keymaps are set by
|maic.setup()|; without it there are none.

                                                                *maic.setup()*
require("maic").setup({opts})
    Merges {opts} over |maic-defaults| and sets the keymaps
    (|maic-keymaps|) unless `keymaps = false`. May be called again: options
    not given return to their defaults, and the keys the last call set are
    removed before the new ones are set.

3. THE INTERFACE                                            *maic-interface*

|:Maic| opens it (with `ui = "nvim"`, the default; |maic-ui|), and
`maic --ui nvim` from the shell starts nvim with it. maic.nvim starts the
engine, `maic --rpc` (|maic-cmd|, |maic-args| and :Maic's arguments), as
this tab's job and speaks MAIC's engine protocol to it over its stdin and
stdout. One interface per tab.

                                                 *maic-conversation* *ft-maic*
The conversation is a buffer of filetype `maic`, highlighted as markdown,
that only maic.nvim writes: `❯` your messages, the replies as they stream,
`⏺` each tool call with its output indented under it, `↯` each steering
action, notices, and `▣ model · time · tool calls` after each turn. A tool's
output of |maic-fold_output| lines or more and the model's reasoning are
folded closed once done; |za| and your own fold keys open them. The winbar
shows the title, model, mode and what MAIC is doing. A window whose cursor is
on the last line follows the stream.

                                                 *maic-input* *ft-maic-input*
The input is a buffer of filetype `maic-input` under it, an ordinary buffer
for your motions, mappings and plugins. <CR> in normal mode or <M-CR> in
insert mode sends it. `/cmd` runs a MAIC command (`/mode plan`, `/model
qwen-9b`), `//text` sends text starting with one slash, `!cmd` runs a shell
command. While a turn runs, what you send goes to it at its next step.

                                                               *maic-floats*
An approval opens a float over the conversation: `y` yes, `n` or <Esc> no,
`N` no with a reason, `a` always, `t` trip the harness, `e` open the file,
`d` (a write) the proposed content against the file as a diff in a new tab,
<C-c> no and cancel the turn. A question lists its options: a digit picks
one, <CR> types an answer, <Esc> gives none. |:Maic| focuses a waiting one.

                                                             *maic-steering*
<C-c> cancels the turn (or stops a running `!cmd`). <C-s> pauses it and
opens the pause menu: <C-q> resumes, `s` steer, `d` drop, `f` further,
`k` keep, `h` halt; what is in the input goes with `s`, `d` and `f` as their
note. <Esc> closes the menu to type a message, which resumes the turn when
sent. <C-q> resumes from either buffer, and |:MaicSteer| does any of them.
The keys are |maic-buffer_keymaps|.

                                                              *maic-history*
A resumed session shows its last three exchanges, and a reply or a command
still running as it goes on. While earlier history is left, the first line
says so: moving the cursor there, or |:MaicOlder|, loads the ten exchanges
before what is shown, above it.

                                                             *maic-sessions*
A tab's engine holds every session opened in it, each with a conversation
buffer of its own under the tab's one input. |:MaicNew|, |:MaicSwitch|,
|:MaicFork|, |:MaicBg|, |:MaicPark| and |:MaicStop| move between them; the
session left becomes what `leave.switch` in MAIC's settings says (by
default a working one goes to the background, and is parked once its work
ends, and an idle one is parked), unless --bg, --park or --stop says
otherwise; a case set to "ask" asks with |vim.ui.select()|. Quitting nvim
ends the tab's engine as MAIC's `:q` does (`leave.quit`). A background
session keeps writing its buffer; its approvals and
questions wait until you switch to it, with one notification naming it. The
winbar counts the other sessions. A parked or stopped session's buffer goes
once no window shows it.

maic.nvim fires the |maic-events| itself and runs |:checktime| after MAIC
writes a file. Closing nvim ends the engine, which parks its sessions.

==============================================================================
4. COMMANDS                                                  *maic-commands*

                                                                       *:Maic*
:Maic [args]
    Opens MAIC in the configured layout (|maic-open|), or focuses the one
    this tab already has, showing its windows again if they were hidden:
    the interface (|maic-interface|), or MAIC's TUI in a terminal with
    `ui = "terminal"` or arguments only the TUI takes (`-p`, `-i`, `-c`,
    `-r`, `--context`, `--image`, `--fork-at`, `--bare`, a prompt). One MAIC
    per tab, reused. [args] are added to the command line when MAIC starts,
    after |maic-args|: >vim
        :Maic --model qwen-9b
        :Maic -c
<    With `open = "tab"` MAIC has a tab of its own and :Maic goes there.

                                                               *:MaicTerminal*
:MaicTerminal [args]
    MAIC's own TUI in a terminal, as |:Maic| with `ui = "terminal"`.

                                                                    *:MaicNew*
:MaicNew [--bg|--park|--stop] [DIR]
    Another session in this tab's engine, in focus; with DIR, `/cd DIR`
    follows. See |maic-sessions|.

                                                                 *:MaicSwitch*
:MaicSwitch [--bg|--park|--stop] [ID|TITLE]
    Goes to another session: a loaded one, a parked one (resumed), or any
    transcript by id. Alone, the switcher (|vim.ui.select()|): a new session
    first, then every other with what it is doing, its model and workspace.

                                                                   *:MaicFork*
:MaicFork [--bg|--park|--stop]
    Forks this session into a second one and goes to it.

                                                                     *:MaicBg*
:MaicBg
    Sends this session to the background, where it keeps working, and opens
    the switcher to pick where to go.

                                                          *:MaicPark* *:MaicStop*
:MaicPark [ID]
:MaicStop [ID]
    Ends this session (through the switcher, to pick where to go) or session
    ID: park for now (it resumes where it was), stop for good (it stays a
    transcript). A working one is asked about first.

                                                                  *:MaicOlder*
:MaicOlder
    Loads the conversation's ten exchanges before the oldest one shown,
    above it. See |maic-history|.

                                                                  *:MaicSteer*
:MaicSteer {action} [note]
    Steers the interface's running or paused turn: `steer`, `drop` and
    `further` (with [note], else what is in the input), `interrupt`
    (pauses), `keep`, `halt`. See |maic-steering|.

                                                                 *:MaicToggle*
:MaicToggle
    Hides this tab's MAIC windows (MAIC keeps running) or shows them again.
    Starts MAIC when there is none.

                                                                   *:MaicSend*
:[range]MaicSend
    With a range, those lines as a fenced snippet headed with the path and
    the line numbers: >
        `src/agent.cpp` lines 120-124:
        ```cpp
        ...
        ```
<    The fence is longer than any run of backticks inside. Without a range,
    the buffer's path in backticks, for the agent to read itself. In visual
    mode the selection is the range; `:%MaicSend` sends the whole buffer.

    When MAIC is connected to this nvim the text goes over its channel
    (`rpcnotify(chan, "maic_send", text)`). When it is not, it is typed into
    this tab's MAIC terminal as a bracketed paste (ESC [200~ ... ESC [201~),
    which MAIC takes into its input whole, in any mode. Either way it is not
    sent to the model.

                                                            *:MaicDiagnostics*
:MaicDiagnostics[!]
    This buffer's diagnostics (|vim.diagnostic.get()|), one line each: >
        src/a.c:12:5: error: expected ';' [clangd]
<    With [!], every buffer's.

                                                              *:MaicInterrupt*
:MaicInterrupt
    Stops MAIC's running turn as its first Ctrl-C does, from any window. In
    the interface it cancels the turn (or a running `!cmd`). When MAIC is
    connected it goes over its channel
    (`rpcnotify(chan, "maic_interrupt")`): a running turn, `!` command or
    pending approval is stopped, and an idle MAIC only says so (your draft
    stays). Without a connection, Ctrl-C is typed into this tab's MAIC
    terminal.

                                                               *:MaicQuickfix*
:MaicQuickfix
    The quickfix list, `path:line:col: type: text` per item; an item with no
    location is its text alone. The list's title heads it.

==============================================================================
5. OPTIONS                                                    *maic-options*

                                                               *maic-defaults*
Every option lives in one table, `require("maic").defaults`. |maic.setup()|
deep-merges your {opts} over it (`vim.tbl_deep_extend("force", ...)`),
which is what lazy.nvim's `opts` passes, so you name only what you change: >lua
    require("maic").setup({ open = "float", keymaps = { quickfix = false } })
<
The table, as shipped: >lua
    {
      cmd = "maic",
      args = {},
      ui = "nvim",
      open = "vsplit",
      size = nil,
      prefix = "<leader>m",
      keymaps = {
        open = "<leader>mm",
        toggle = "<leader>mt",
        send = "<leader>ms",
        send_selection = "<leader>ms",
        send_buffer = "<leader>mb",
        diagnostics = "<leader>md",
        workspace_diagnostics = "<leader>mD",
        quickfix = "<leader>mq",
        interrupt = "<leader>mc",
      },
      buffer_keymaps = { interrupt = "<C-c>", pause = "<C-s>", resume = "<C-q>",
                         send = "<CR>", send_insert = "<M-CR>" },
      input_height = 6,
      fold_output = 4,
      terminal_escape = "<C-\\><C-n>",
      terminal_passthrough = { ["<Esc>"] = true, ["<C-c>"] = true },
      filetypes = { conversation = "maic", terminal = "maic", input = "maic-input" },
    }
<
Read it from Lua to build on it, never to change it: >lua
    print(vim.inspect(require("maic").defaults.keymaps))
<
                                                                    *maic-cmd*
cmd         The program: a name on PATH, a path, or a list of the program
            and its arguments (`{ "maic", "--harness", "dumb" }`).

                                                                   *maic-args*
args        Arguments for every start, before those given to |:Maic|.

                                                                     *maic-ui*
ui          "nvim": |:Maic| opens the interface (|maic-interface|).
            "terminal": MAIC's own TUI in a terminal.

                                                                   *maic-open*
open        Where MAIC opens: "split" (below), "vsplit" (right), "float"
            (centred, rounded border) or "tab" (a tab of its own).

                                                                   *maic-size*
size        "split": rows (default 15). "vsplit": columns (default 40% of
            the screen). "float": a fraction of the editor (default 0.8).

                                                                 *maic-prefix*
prefix      Where the default keymaps live: a default key that starts with
            `<leader>m` moves under it. Keys you name in `keymaps` stay
            exactly as you give them.

                                                           *maic-keymaps-opt*
keymaps     A table of name = key (|maic-keymaps|); merged over the
            defaults, so a table moves or drops single ones by name. false:
            none. true: the defaults. >lua
                keymaps = { send = "<leader>ss", quickfix = false }
<
                                                         *maic-input_height*
input_height
            The interface's input: rows under the conversation.

                                                          *maic-fold_output*
fold_output
            A tool's output of at least this many lines is folded closed in
            the conversation once it is done. false: never.

                                                        *maic-terminal_escape*
terminal_escape
            The key that leaves terminal mode in MAIC's terminal. The
            default is nvim's own |t_CTRL-\_CTRL-N|, which needs no mapping;
            any other key is mapped buffer-local there. See |maic-esc|.

                                                   *maic-terminal_passthrough*
terminal_passthrough
            Keys that reach MAIC in its terminal even when a global
            terminal-mode mapping holds them: `key = true`, `false` drops one.
            Each is a buffer-local, |:map-nowait| |:tnoremap| of the key to
            itself in MAIC's terminal only. >lua
                terminal_passthrough = { ["<C-w>"] = true }
<
                                                         *maic-filetypes*
filetypes   MAIC's buffers get these filetypes so plugins can include or
            exclude them: `conversation` and `input` (the interface's
            buffers) and `terminal` (MAIC's terminal, set before the job
            starts, so a |TermOpen| autocmd sees it).

6. KEYMAPS                                                    *maic-keymaps*

Set by |maic.setup()|; the name is the key in the `keymaps` table.

    name                    keys          mode     does ~
    open                    <leader>mm    normal   |:Maic|
    toggle                  <leader>mt    normal   |:MaicToggle|
    send                    <leader>ms    normal   |:MaicSend| (the path)
    send_selection          <leader>ms    visual   :'<,'>MaicSend
    send_buffer             <leader>mb    normal   :%MaicSend
    diagnostics             <leader>md    normal   |:MaicDiagnostics|
    workspace_diagnostics   <leader>mD    normal   :MaicDiagnostics!
    quickfix                <leader>mq    normal   |:MaicQuickfix|
    interrupt               <leader>mc    normal   |:MaicInterrupt|

                                                      *maic-buffer_keymaps*
In MAIC's own buffers only, buffer-local (`buffer_keymaps`, same names):

    name          keys      mode           where              does ~
    interrupt     <C-c>     normal         every MAIC buffer  |:MaicInterrupt|
    pause         <C-s>     normal, insert conversation, input  pauses the turn
    resume        <C-q>     normal, insert conversation, input  resumes it
    send          <CR>      normal         input              sends the input
    send_insert   <M-CR>    insert         input              sends the input

(insert mode for pause and resume in the input only)

and <C-c> in terminal mode is passed through to MAIC, whose own Ctrl-C
interrupts (|maic-terminal_passthrough|). <C-c> is never mapped globally.

                                                                   *maic-esc*
In MAIC's terminal, <Esc> goes to MAIC, whose input is vim-like and needs it
for normal mode, even when you have the common >vim
    tnoremap <Esc> <C-\><C-n>
<a global mapping that makes <Esc> leave terminal mode. maic.nvim maps <Esc>
to itself buffer-local in MAIC's terminal (|maic-terminal_passthrough|), so
your mapping keeps working in every other terminal. To leave terminal mode in
MAIC's, press <C-\><C-n>, or set |maic-terminal_escape| to a key of your
own. A |TermOpen| autocmd that maps keys in every terminal can skip MAIC's: >lua
    if vim.bo[ev.buf].filetype == "maic" then return end
<
                                                       *maic-never-overwrite*
maic.nvim never overwrites a mapping. Before it sets a default key it asks
|maparg()| and |mapcheck()| for that mode: when another mapping holds the key,
or shares a prefix with it (so one of the two would wait 'timeoutlen'), the
key is skipped. Every skipped key is reported once per session in one
|vim.notify()| warning, naming the key, the mode and what holds it: the
mapping's description or right-hand side and the script and line that set
it. Mappings made from Lua name their file only when nvim runs with -V1;
otherwise the warning says "Lua". >
    maic.nvim never overwrites a mapping:
      <leader>mq (normal) skipped, held by "Quickfix list" from ~/.config/nvim/lua/keys.lua:12
<
A key you name in `keymaps` is set even when something holds it, since you
chose it, and is reported the same way as shadowing what held it. The keys
maic.nvim sets in its own buffers are buffer-local and never touch your
global mappings. |:checkhealth| maic lists every key.

                                                    *maic-health* *maic-check*
:checkhealth maic
    Lists every key maic.nvim sets (global, and buffer-local in MAIC's own
    buffers), the keys MAIC's own input needs in its terminal (<Esc>,
    <C-w>, <C-p>, <S-Tab>, <C-z>, <C-c>, <M-CR>) and, when llama.vim is
    installed (`g:llama_config` is set or its autoload/llama.vim is on
    'runtimepath'), every key llama.vim uses, against your mappings in the
    modes each is used in. Your buffer-local mappings are collected too: the
    check opens a plain file buffer, scratch buffers of filetypes
    `maic-input` and `maic` and a terminal of filetype `maic` in a tab of its
    own, reads
    what your FileType, BufEnter and TermOpen autocmds mapped there, and
    closes them again.

    Each key is one line: OK when it is free (or a passthrough makes it
    reach MAIC), WARN when maic.nvim skipped it, a key you named shadows
    something, two mappings share a prefix so one waits 'timeoutlen', or an
    insert-mode key starts with a key that types (with a <Space> leader,
    llama.vim's default insert-mode <leader>llf makes every typed space
    wait), and ERROR when a key MAIC needs never reaches it in its terminal.
    Every WARN and ERROR comes with the fix. `maic nvim keymaps` runs the
    same check outside nvim, against your config.

7. EVENTS                                                      *maic-events*

A connected MAIC fires |User| autocmds in this nvim with
|nvim_exec_autocmds()|, and the interface fires the same ones as it shows
the engine's events. Every `data` has `session`, MAIC's session id; the rest
as applies:

                                                               *MaicTurnStart*
MaicTurnStart       A turn starts. `model`.
                                                                *MaicToolCall*
MaicToolCall        The model calls a tool. `tool`, `path` (absolute, "" for
                    none), `summary`.
                                                                *MaicApproval*
MaicApproval        MAIC asks you to approve something, with `verdict` =
                    "pending"; then again with your answer, `verdict` =
                    "yes", "no", "always" or "trip". `tool`, `path`,
                    `summary`, `reason`.
                                                             *MaicFileWritten*
MaicFileWritten     A tool changed a file (a write, an edit, a patch, a
                    move's two ends, a delete). `tool`, `path`.
                                                                 *MaicTurnEnd*
MaicTurnEnd         The turn is over. `model`, `tool_calls`, `seconds`,
                    `interrupted`.

Example: >lua
    vim.api.nvim_create_autocmd("User", {
      pattern = "MaicApproval",
      callback = function(ev)
        if ev.data.verdict == "pending" then
          vim.notify("MAIC asks: " .. ev.data.summary, vim.log.levels.WARN)
        end
      end,
    })
    vim.api.nvim_create_autocmd("User", {
      pattern = "MaicFileWritten",
      callback = function(ev) print("MAIC wrote " .. ev.data.path) end,
    })
<
MAIC also runs |:checktime| after it changes a file, so an open buffer
reloads (or asks, when it has unsaved changes).

8. LUA                                                            *maic-lua*

require("maic") has, besides |maic.setup()|:

open({args})                                                  *maic.open()*
    |:Maic| with a list of arguments.

toggle()                                                    *maic.toggle()*
    |:MaicToggle|.

interrupt()                                              *maic.interrupt()*
    |:MaicInterrupt|. Returns "engine" (the interface), "rpc", "key"
    (Ctrl-C into the terminal) or nil (no MAIC here).

send_text({text})                                        *maic.send_text()*
    Puts {text} into MAIC's input, never sent. Returns "input" (the
    interface's input buffer), "rpc" (over MAIC's channel), "paste" (into
    this tab's terminal) or nil (no MAIC here).

command({line})                                            *maic.command()*
    Runs a command line in MAIC as if typed: >lua
        require("maic").command(":mode plan")
<    In the interface it goes to the engine. Returns false when no MAIC is
    connected.

require("maic.ui").state()                                    *maic.ui.state()*
    This tab's interface as plain values, for a statusline: `session`,
    `response` (nil when idle), `paused`, `activity`, `mode`, `model`,
    `conversation` and `input` (buffers), `float`. nil without one.

channel()                                                  *maic.channel()*
    MAIC's channel: the client named "maic" whose pid is this tab's
    terminal job; with no MAIC terminal in the tab, the newest "maic"
    client. nil when MAIC is not connected.

format_snippet({path}, {first}, {last}, {lines}, {filetype})
format_diagnostics({items})
format_quickfix({items})
    The formatters behind the commands, for your own mappings.

9. MAIC'S SIDE                                                   *maic-host*

nvim sets $NVIM to its socket for every job. MAIC connects to it as a
msgpack-rpc client named "maic" only when it is a Unix socket owned by you
and the nvim behind it (SO_PEERCRED) runs as you and is one of MAIC's parent
processes; anything else is refused, and the first line in MAIC says why.
MAIC's status strip shows `nvim` while connected; `:nvim` in MAIC says more.

Connected:
- `:e FILE` and `e` at an approval prompt open the file here with |:drop|,
  in the window you edit in (not MAIC's terminal).
- `d` at an approval prompt for a write opens a new tab with the file
  against a read-only scratch buffer holding the proposed content, both in
  |diff-mode|.
- MAIC's theme follows your colorscheme live, read with |nvim_get_hl()|
  after every |ColorScheme| (`follow_nvim_theme` in MAIC's settings).
- MAIC's own Lua gets `maic.nvim.exec`, `buffers`, `diagnostics` and
  `current`, which run here.
- The model gets a `diagnostics` tool, judged as a read like any read. It
  can never run Lua here or change a buffer: its edits are file writes
  through MAIC's harness, which this nvim then reloads.
- |:MaicInterrupt| reaches it as `maic_interrupt`.

`maic --bare` (or `MAIC_BARE=1`) never connects, even inside nvim: then
|:MaicSend| falls back to the bracketed paste and |:MaicInterrupt| to
typing Ctrl-C. MAIC's status strip shows `bare`; `:h bare` in MAIC.
