# v0.3.4 (2026-10-02)

MAIC now has an engine, and its own interface is the engine's first client. This is the foundation for nvim as MAIC's interface, background sessions and the remote app: they all speak the same protocol.

## New

* **The engine** (`core/src/engine.cpp`): it owns the sessions, emits OpenAI-named events (`response.created`, `response.output_text.delta`, `response.shell_call_output_content.delta`, `response.completed`, ...) with MAIC's own under `maic.`, numbers them per session with `sequence_number`, resumes with `starting_after`, and checks every message against the protocol's schemas and ordering rules (the `guarded` tier). See [design/engine-protocol.md](../design/engine-protocol.md).
* **The protocol as files**: `protocol/maic.openrpc.json` (OpenRPC), JSON Schemas that reference OpenAI's shapes rather than restating them, and `ordering.json` with the state machines; all built into the binary.
* **`maic protocol check FILE|DIR`** replays recorded streams and reports the first violation. `MAIC_PROTOCOL_RECORD=DIR` makes the TUI or `maic -p` record their stream.
* **The TUI and `maic -p` run on the engine** in-process. Nothing visible changes.

## maic-server and the web client

* A remote "always" is refused; the web client's Always button is gone.
* A remote switch to `auto` mode needs the step-up check.
* A message sent mid-turn waits for the model's next step instead of aborting the call in progress.
* Remote clients no longer see the transcript's file path.
* Server sessions honour `harness` and `reviewer_model` from settings, as the TUI does.
* `?after=N` still works; the event field `seq` is now `sequence_number` (the last event's number).
