# v0.3.3 (2026-10-02)

## Fixes

* **The model was told the wrong number of omitted bytes.** When a command's output passed 128 KiB, the "[N bytes omitted]" note in what the model received undercounted, by a different amount from run to run (a 1 MiB output reported 61K to 94K omitted instead of about a million). The bytes the model saw were always right; the count now is too.
* **"Broken pipe" errors in sandboxed pipelines under maic-server.** The server's ignored SIGPIPE was inherited into the sandbox, so `seq ... | head` complained. Sandboxed programs now get the default signal handling.

## New

* **Live tool output.** A running command's output appears under its tool call as it arrives (the last lines, carriage returns honoured), and remote clients receive it as `response.shell_call_output_content.delta` events, limited to 64 KiB/s per session. What the model receives is unchanged, byte for byte.
* **The full output, kept and labelled.** When a command's output passes the model's cap, the whole stream is kept beside the session with a timing index, marked everywhere as "full output, display only: the model saw the capped result". `maic sessions output ID CALL --replay` plays it back as it happened. See [sessions.md](../sessions.md#full-output).
* **OpenAI's API description, pinned.** The full file from openai/openai-openapi at `de3a025` lives in `protocol/openai/` (MIT), with the subset MAIC uses extracted by script, MAIC's own JSON Schema validator, and tests that hold MAIC's OpenAI-compatible client and its test servers to the official shapes. See [standards.md](../standards.md).
* **Adapter normalizations.** Where a server departs from OpenAI's shapes, MAIC fixes it at the boundary and counts each fix in the session: llama.cpp's numeric error code becomes `maic_llamacpp_500` with `param: null` and the original kept under `maic.upstream`; a log-probabilities chunk without `refusal` gets `refusal: null`. Providers gain an `upstream` field naming the software behind them.
* **The audit trail, off by default.** For people who want unrecorded sessions to stay auditable: tool calls and the harness's decisions only, never conversation text or output, with rolling live, stale-live and archival states, optional archive chunks, scheduled or start-up audits, and printed off-site commands. Everything is in `~/.config/maic/audit.lua`. See [audit-trail.md](../audit-trail.md).
* **The leak audit's judges think by default** (`judge_thinking`, `--thinking on|off`), with their reasoning in the private report only.

## You may notice

* `maic-leak-audit` reads its settings through `maic audit-trail status`, and refuses to run when `audit.lua` is broken rather than falling back to defaults.
