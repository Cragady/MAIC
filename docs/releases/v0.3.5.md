# v0.3.5 (2026-10-02)

Steering, and the engine on stdio for maic.nvim.

## New

* **Steering.** A message typed mid-turn goes out as OpenAI's `response.steer` and lands at the model's next step. `maic.steer` adds six actions: `steer`, `drop` and `further` redirect with a note (`drop` also trims the reply being written), `interrupt` pauses, `keep` ends the turn with the reply so far, `halt` discards it. A steer withdraws a waiting approval.
* **Pause keys.** Ctrl-S pauses a running turn and opens a small menu: Ctrl-Q resumes, `s`, `d`, `f`, `k`, `h` pick an action. Terminal flow control is turned off so the keys get through. `:steer ACTION [NOTE]` and `:steering` do the same from the prompt.
* **Queued turns.** A message sent while a turn runs with `response.create` waits its turn (first in, first out); cancelling it takes it off the queue.
* **`steering` settings.** Choose which actions clients may use; a project can only remove actions. A ban can name a steer action, and one that keeps firing escalates to `halt`.
* **`maic --rpc`.** The engine on stdin and stdout as JSON-RPC lines, started like the TUI with the same flags and settings. It opens no session itself; the client creates or resumes one. This is what maic.nvim's interface mode will speak.
* maic-server's web client steers mid-turn too.

## Changed

* Events from a local client are named by the client's hello (`maic.nvim`), not `stdio`.
* With `record = false`, protocol sessions (maic-server's included) write their transcript to the runtime directory, as the TUI does.
