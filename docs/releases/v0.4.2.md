# v0.4.2 (2026-10-03)

Degraded beats halted: one bad item degrades only itself, says so, and the rest keeps working (docs/decisions.md, "Discipline after the MAID_VENDOR cascade").

## Fixed

* A provider error no longer can kill the TUI, daemon or server: the optional hint it builds is dropped if it fails.
* `:cd`, `:path`, `:open` and their shell completion survive a bad settings file, vendor manifest or artifact.
* Start, the daemon, headless runs, `--rpc` and `:model` survive a corrupt vendor manifest; models roots no longer re-read settings.
* Settings degrade per item: a bad preset, provider, judge, preset name or ban steer is skipped with a warning; an agent that fails narrowing is removed; an `audit.lua` error is raised only by the audit itself; a broken project layer is skipped with a warning unless it names a guarded field (permissions, forbid, harness, tripwire, agents, profiles and similar), which is still refused.
* One unreadable transcript no longer breaks `maid -r`, `maid sessions` or resume of the others.
* `:status`, `:cd`, `maid status`, `maid up/down/logs` report skipped service files and keep working; a missing services directory says where it looked.
* The audit judge's service start and `--ctx` restarts at start report and continue.
* A malformed catalog entry is skipped; the rest stay priced.
* `maid doctor` reports settings, audit, manifest and service problems as findings.
* `maid server status` reports a corrupt pairing file (`maid server start` still refuses it).
* A missing `HOME` no longer crashes instruction, catalog, tools or diction-log lookups.
* The checkout's harness files stay protected under an installed build.

## Moved

* The checkout is now `~/dev2/MAID`.
