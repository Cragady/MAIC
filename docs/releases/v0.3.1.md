# v0.3.1 (2026-10-01)

A security release: two fixes to the harness, nothing else.

## Security

* **The command sandbox could reach host sockets.** `run_shell`, script tools and a Lua tool's `maic.shell` ran in bubblewrap with `/` bound read-only and the environment passed through. A read-only bind does not stop a program connecting to a Unix socket, so a sandboxed command could reach the session D-Bus (`/run/user/$UID/bus`, named by `DBUS_SESSION_BUS_ADDRESS`) and through it ask systemd to start a process outside the sandbox, with the network. The same places held your nvim's socket (code execution in your editor), Wayland, pipewire, gpg-agent, often ssh-agent, the system bus and `docker.sock`. Now all of `/run`, your runtime directory and the directories of the agent sockets are empty inside the sandbox (removable drives under `/run/media` stay readable), and a sandboxed program starts with a cleared environment holding only `PATH`, `HOME`, `USER`, `LOGNAME`, `LANG`, `LC_*`, `TERM`, `TZ`, `SHELL`, `XDG_CONFIG_HOME` and `XDG_STATE_HOME` ([harness.md](../harness.md#layers), rule 6).
* **A local "always" let remote requests through.** After you answered "always" for a program or a file, a later request of the same kind from a remote client (`maic-server`) ran without being asked, and an "always" answered from a client was remembered the same way. A remote request is now asked every time: a terminal "always" never covers it, and "always" from a client counts for that one call (rule 5).

## What you should know

* **If you ran agents in auto mode** (or edit mode, or with commands on your allow list), a command could have used the sockets above without being asked. MAIC cannot know whether that happened. Your session transcripts record every command the agent ran: look for `dbus-send`, `busctl`, `gdbus`, `systemd-run`, `nvim --server` or `--remote`, `socat`, `nc -U`, `docker`, or paths under `/run/user` or `/run`, with `maic sessions` or a search over `~/.local/state/maic/sessions`.
* **A tool that relied on an environment variable** not on the list above no longer sees it. Add it to `kPassedEnv` in `core/src/sandbox.cpp` with the reason, or pass the value in the command.
* **What is still open** is in [limits.md](../limits.md#the-command-sandbox): a socket in some other directory (say one in your home directory) is still reachable.
