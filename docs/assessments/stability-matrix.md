# Stability Matrix: what MAID can take from it

> Note (2026-10-01): Ollama was removed from MAID in favour of llama.cpp (docs/llamacpp.md). The Ollama references below are history.

Assessed 2026-09-30 against the checkout at `~/dev2/tools-and-things/StabilityMatrix` (upstream LykosAI/StabilityMatrix, head `fcfab8b7`, tagged `v2.16.4` plus one merge). Read-only; nothing was built or run. File references are relative to that checkout unless they start with `MAID/`.

**Short answer:** nothing to run next to MAID, a dozen design ideas worth taking into the vendor and service layers, and a clear list of things not to copy. The recommendation and the roadmap-ready items are in section 6.

## 1. What it is

**Stack.** C# on .NET 9 (`global.json`, `Directory.Build.props:3`), Avalonia 11.3 desktop UI (`Directory.Build.props:12`), MVVM with CommunityToolkit, Refit HTTP clients, LiteDB for the local model index (`StabilityMatrix.Core/Database/LiteDbContext.cs:80`, file `StabilityMatrix.db` in the data directory), YamlDotNet for config injection, Octokit for GitHub, Sentry for crash reporting, pythonnet is referenced but the package logic shells out to `uv`, `pip`, `git` and `python` as subprocesses. Six projects: `StabilityMatrix.Core` (package manager, Python, APIs, services), `StabilityMatrix.Avalonia` (UI, prerequisite installers, Inference), `Native`, `Native.Windows`, `Native.macOS`, `Tests` (70 test files), `UITests`.

**Platforms.** Windows x64, Linux x64 (AppImage built with pupnet, `StabilityMatrix.Avalonia.pupnet.conf`, and an AUR package per `README.md:13`), macOS arm64 (dmg, signed and notarized by `Build/*.sh`). Platform switches live in `StabilityMatrix.Core/Helper/Compat.cs:22-38`.

**License.** Source is AGPL-3.0 (`LICENSE`, `README.md` "License" section). Binaries are under Lykos's own EULA (`README.md`, and `AppLicenseId = LicenseRef-Proprietary` in the pupnet config). Under `MAID/docs/cleanroom.md` ("Code under copyleft licenses that would change MAID's licensing (GPL, AGPL)" is not allowed unless deliberately recorded), this repository is **design ideas only**. Nothing from it can be vendored or copied; the behaviour can be reimplemented from a description, which is what this document is for.

**Size and activity.** 64 MB checkout, 1843 tracked files, 1418 `.cs` files. Essentially one author (Ionite, also committing as JT) with one steady contributor (NeuralFault) and a few others. About 980 commits in the last twelve months, about 250 in the last three. Release cadence from the tags: minor versions roughly every six to nine months (2.14.0 April 2025, 2.15.0 September 2025, 2.16.0 June 2026), patch releases every two to six weeks (2.16.1 June 15, 2.16.2 August 1, 2.16.3 August 28, 2.16.4 September 15, 2026). `CHANGELOG.md` is thorough and each entry ends with a supporters section, which tells you the business model: Patreon and a Lykos membership (`StabilityMatrix.Avalonia/Assets.cs:197-201`).

**Distribution.** Self-contained single-file builds (`Jenkinsfile`, `PublishSingleFile=true --self-contained`), published as GitHub releases and mirrored on `cdn.lykos.ai`, plus a built-in self-updater (section 3). Preview and development channels are signed with an Ed25519 key baked into the binary (`StabilityMatrix.Core/Updater/SignatureChecker.cs:8-12`).

**What it is for.** A GUI that installs about thirty Stable Diffusion front ends and trainers into one data directory, gives them one shared model library, launches them with a console view, browses CivitAI and HuggingFace for models, and ships its own generation UI ("Inference") that drives a ComfyUI backend over the ComfyUI HTTP and websocket API (`docs/advanced/comfyui-integration.md`).

## 2. Package management

### The packages

Each package is a C# class deriving from `BaseGitPackage` (`StabilityMatrix.Core/Models/Packages/`). Concrete ones: ComfyUI, ComfyUI-Zluda, A1111 (`stable-diffusion-webui`), A1111 DirectML, SD WebUI UX, SD.Next (`automatic`), Forge, Forge Classic, Forge Neo, reForge, AMDGPU Forge, Fooocus, Fooocus MRE, Fooocus ControlNet SDXL, Ruined Fooocus, mashb1t Fooocus, SimpleSDXL, InvokeAI, SwarmUI, SDFX, VoltaML, Kohya's GUI, OneTrainer, FluxGym, AI Toolkit, Wan2GP, FramePack, FramePack Studio, CogStudio, DankDiffusion, and `UnknownPackage` for imported folders it cannot classify. There is no data-driven package manifest: adding a package means writing a class with its launch options, shared folder layout, torch index list and install steps.

### Install and update

- **Where things go.** One data directory (`docs/getting-started/data-directory.md`): `Packages/<name>` per install, `Models/` shared library, `Images/` shared outputs, `Assets/` for every tool it downloads (uv, Python, 7-Zip, Node, .NET SDK, ffmpeg, PortableGit on Windows), `Workflows/`, `Tags/`, `.downloads/`, `settings.json`, `StabilityMatrix.db`. A `.sm-portable` marker makes the whole thing relocatable.
- **Fetching.** Version options come from the GitHub API (releases, branches, commits; `BaseGitPackage.cs:102-178`), cached 15 minutes in LiteDB (`StabilityMatrix.Core/Helper/Cache/GithubApiCache.cs:16`). Install is `git clone` at a tag or branch and an optional `git checkout <sha>` (`BaseGitPackage.cs:296-345`). Nothing is checksum-verified at the git level; trust is in GitHub.
- **Updating.** `Update` (`BaseGitPackage.cs:477-640`) runs `git init` plus `remote add` if the folder is not a repo, temporarily removes model symlinks, then either `fetch --tags --force` and `checkout <tag> --force` and a full reinstall of requirements, or for branch installs `fetch`, `checkout <branch> --force`, `pull --ff-only --autostash`, falling back to `pull --rebase --autostash`. `CheckForUpdates` (`388-427`) compares the installed tag to the latest GitHub release, or the installed sha to the branch head. Each installed package records tag or branch plus commit, `PythonVersion`, `PreferredTorchIndex`, `PreferredSharedFolderMethod`, `LaunchArgs`, `PipOverrides`, `LastUpdateCheck` (`StabilityMatrix.Core/Models/InstalledPackage.cs:13-58`).
- **Pinning.** There is no pin file. A package tracks whatever the user chose: a release tag, or a branch head (default for packages that "ignore releases"). The app's job is to keep you current; staying on a fixed ref is a manual choice per install.

### Python, venv, uv

- **Its own Python.** uv 0.12.5 is downloaded from GitHub releases into `Assets/uv` (`StabilityMatrix.Avalonia/Helpers/UnixPrerequisiteHelper.cs:37-40`, `WindowsPrerequisiteHelper.cs:58-59`). Interpreters are uv-managed under `Assets/Python` via `UV_PYTHON_INSTALL_DIR` (`StabilityMatrix.Core/Python/UvManager.cs:50-57, 117-121`), listed with `uv python list --managed-python --output-format json` (`UvManager.cs:111`). Known targets are 3.10.11 (legacy, downloaded from python.org or `cdn.lykos.ai` with a sha256, `Assets.cs:101-127`), 3.10.17, 3.11.13, 3.12.10, 3.13.12 (`StabilityMatrix.Core/Python/PyInstallationManager.cs:18-22`). ComfyUI defaults to 3.12.10 (`ComfyUI.cs:59`). The system Python is never used.
- **venv.** `venv/` inside the package directory, created by `uv venv --python <path>` (`StabilityMatrix.Core/Python/UvVenvRunner.cs:152-155`); installs go through `uv pip install --index-strategy unsafe-first-match --python <venv python>` (`UvVenvRunner.cs:250-253`). Only the legacy 3.10.11 path still uses `python -m pip` (`PyInstallation.cs:119`, `PyVenvRunner.cs:224-243`). `UV_CACHE_DIR` is forced into the data directory (`StabilityMatrix.Core/Models/Settings/Settings.cs:172-177`), `PIP_DISABLE_PIP_VERSION_CHECK=1` is a default env var (`Settings.cs:152-158`), and a `setuptools<82` build constraint is written into `venv/uv-build-constraints.txt` and passed as `UV_BUILD_CONSTRAINT` / `PIP_CONSTRAINT` so source builds of old custom nodes still work (`BaseGitPackage.cs:256-266`, `ComfyUI.cs:964-979`). This is the same shape as MAID's `vendor/comfyui.sh` (uv venv, uv pip), just with the interpreter store moved under the app's own directory.

### CUDA, ROCm and torch selection

`BasePackage.GetRecommendedTorchVersion` (`StabilityMatrix.Core/Models/Packages/BasePackage.cs:135-182`) walks NVIDIA, then Zluda, Intel (IPEX), ROCm on Linux, DirectML on Windows, MPS on Apple Silicon, then CPU, using `HardwareHelper` (`nvidia-smi`, `lspci` on Linux, WMI on Windows; `StabilityMatrix.Core/Helper/HardwareInfo/HardwareHelper.cs:74-85, 214`). ComfyUI overrides it to prefer ROCm when an AMD GPU is present, including the native Windows ROCm path (`ComfyUI.cs:727-739`). The pip arguments are built by `GetTorchPipArgs` (`BaseGitPackage.cs:960-1000`): `torch torchvision torchaudio --extra-index-url https://download.pytorch.org/whl/<index>`, with `cu130` by default, `cu126` for GPUs below compute capability 7.5 (`HardwareHelper.cs:303-307`, `ComfyUI.cs:489-494, 529`), `rocm7.2`, `xpu`, `cpu`. Windows ROCm torch comes from AMD's repositories (`StabilityMatrix.Core/Models/Rocm/WindowsRocmSupport.cs:11-12`). Before launch, if the venv's torch is `+cu130` and `nvidia-smi` reports a driver older than 580, launch is aborted with a boxed warning (`BaseGitPackage.cs:887-950`). A RTX 2070 is compute capability 7.5, so it gets `cu130`, the same choice MAID made in `MAID/vendor/comfyui.sh`.

Optional accelerators (Triton, SageAttention, Nunchaku, Flash Attention) are installed from wheels found by matching torch version and Python tag against GitHub release assets (`StabilityMatrix.Core/Services/PipWheelService.cs:128-149, 397-415`) or built from source with helper libraries from `cdn.lykos.ai` (`PipWheelService.cs:307, 334`).

### Custom nodes

ComfyUI's extension manager (`ComfyUI.cs:763-1008`) reads two JSON manifests over the network: ComfyUI-Manager's `custom-node-list.json` and Lykos's own `ComfyUI-Extensions-Index`, both via jsdelivr (`ComfyUI.cs:773-774`). It does not query `registry.comfy.org` itself. Install is `git clone` into `custom_nodes/`, then `requirements.txt` and `install.py` run inside the venv with `COMFYUI_PATH` and `COMFYUI_MODEL_PATH` set (`ComfyUI.cs:875-1008`, env at `982-989`). Separately, a fresh ComfyUI install pip-installs `manager_requirements.txt` (that is `comfyui_manager==4.2.2` in ComfyUI v0.38) and turns on `--enable-manager` by default (`ComfyUI.cs:383-385, 599-620`), so the in-browser ComfyUI-Manager is live, and that component talks to the registry on its own. Extension detection tolerates registry-unpacked folders without git metadata (`StabilityMatrix.Core/Models/Packages/Extensions/ExtensionMatcher.cs:7-8`). Workflows saved by ComfyUI carry `cnr_id` / `aux_id` per node; `StabilityMatrix.Core/Helper/WorkflowNodeAnalyzer.cs:20-33` reads them to list missing node packs, which is a purely local computation.

### Model browser

- **CivitAI.** Public REST API (`StabilityMatrix.Core/Api/ICivitApi.cs:10-26`) at `https://civitai.com` (`App.axaml.cs:724-727`). Optional API key stored in an encrypted secrets file and sent as a bearer token only for `civitai.com` downloads (`StabilityMatrix.Core/Services/DownloadService.cs:404-441`). An optional Lykos proxy, `discovery.lykos.ai`, is off by default (`Settings.cs:286`, `StabilityMatrix.Core/Api/CivitCompatApiManager.cs:24-74`). There is also an unofficial tRPC fallback that spoofs `Referer` and `Origin` headers to look like the CivitAI website (`StabilityMatrix.Core/Api/ICivitTRPCApi.cs:7-29`). CivArchive is a second browser (`StabilityMatrix.Core/Api/CivArchiveApiClient.cs:18`), OpenModelDB a third for upscalers (`IOpenModelDbApi.cs:10-20`).
- **HuggingFace.** Not a search; a curated list shipped in the binary (`StabilityMatrix.Avalonia/Assets/hf-packages.json`) plus an optional token that is only sent to `huggingface.co` (`IHuggingFaceApi.cs:9-10`, `DownloadService.cs:427-441`).
- **NSFW.** The CivitAI request always asks for `nsfw=true` and the app filters client-side (`StabilityMatrix.Avalonia/ViewModels/CheckpointBrowser/CivitAiBrowserViewModel.cs:397, 739`), gated by `ModelBrowserNsfwEnabled` and `ShowNsfwInCheckpointsPage` (`Settings.cs:81, 265`), both off by default.
- **Downloads.** Resumable with `Range` (`DownloadService.cs:134-274`), sha256-verified against the CivitAI file record when one exists (`StabilityMatrix.Core/Models/TrackedDownload.cs:48-62, 149-158`), and each model gets two sidecars: `<name>.cm-info.json` (CivitAI metadata, hashes, trained words, base model; `StabilityMatrix.Core/Models/ConnectedModelInfo.cs:11-43`) and `<name>.preview.<ext>`.

### Shared model folders (the exact mechanism)

Two mechanisms, chosen per install (`BasePackage.cs:112-133`, `docs/advanced/shared-folders.md`):

1. **Symlink / junction.** `SharedFolders.CreateOrUpdateLink` (`StabilityMatrix.Core/Helper/SharedFolders.cs:60-141`) makes `Packages/<pkg>/models/<x>` a link to `Models/<Category>`. Windows gets an NTFS junction created through `DeviceIoControl(FSCTL_SET_REPARSE_POINT)` with the mount point tag (`StabilityMatrix.Core/ReparsePoints/Junction.cs:43-104`), other platforms a directory symlink (`SharedFolders.cs:38-50`). If the package folder already has files, they are **moved** into the shared category first (`SharedFolders.cs:119-136`). A link that would sit inside its own target is refused (`80-98`, added after a workflow-folder loop froze the app, `CHANGELOG.md` v2.16.4). Removal only ever deletes links, never real directories (`189-225`). An option removes all links at shutdown (`324-359`).
2. **Configuration.** For packages with a path file, a `SharedFolderLayout` (`ComfyUI.cs:62-224`) maps shared categories to config keys, and `SharedFoldersConfigHelper` (`StabilityMatrix.Core/Helper/SharedFoldersConfigHelper.cs:23-103`) rewrites the file through a per-format strategy (YAML, JSON, SwarmUI's FDS; `10-17`). For ComfyUI this writes `extra_model_paths.yaml` with a `stability_matrix:` root key (`ComfyUI.cs:69`), each key a multi-line literal scalar of absolute paths, leaving other top-level keys alone (`StabilityMatrix.Core/Models/Packages/Config/YamlConfigSharingStrategy.cs:100-148`; shape visible in `StabilityMatrix.Tests/Models/Packages/SharedFolderConfigHelperTests.cs:253-262`). Turning sharing off calls `UpdateConfigFileForDefaultAsync`, which clears that root key (`SharedFoldersConfigHelper.cs:109-173`). ComfyUI's recommended method is Configuration (`ComfyUI.cs:58`).

The category list is a flags enum of 36 types (`StabilityMatrix.Core/Models/SharedFolderType.cs`), and the ComfyUI layout covers checkpoints, diffusers, loras (Lora and LyCORIS merged), clip, clip_vision, embeddings, vae, vae_approx, controlnet (with T2I adapters), gligen, upscale_models (ESRGAN, RealESRGAN, SwinIR), hypernetworks, ipadapter, prompt_expansion, ultralytics (plus bbox and segm subkeys), sams, diffusion_models, style_models, audio_encoders, model_patches, background_removal. That mirrors `folder_paths.py`.

### Outputs and workflows

Output sharing is the symlink mechanism again: ComfyUI's `output/` becomes a link to `Images/Text2Img` (`ComfyUI.cs:226-227`, `BaseGitPackage.cs:836-858`); Inference writes to `Images/Inference`. The app's own workflow library is linked into every ComfyUI install as `user/default/workflows/Stability Matrix` (`ComfyUI.cs:239-267`). Generated images are indexed by reading the PNG text chunks `parameters`, `parameters-json` and `prompt` (`StabilityMatrix.Core/Helper/ImageMetadata.cs:110-118`).

### Checkpoint scanning

`ModelIndexService` (`StabilityMatrix.Core/Services/ModelIndexService.cs`) walks `Models/`, records each file in LiteDB with BLAKE3 and SHA-256 sets (`37-60`), reads the `.cm-info.json` and preview sidecars (`346-382`), and can hash files (`StabilityMatrix.Core/Helper/FileHash.cs:42-80`) to look them up on CivitAI by hash (`StabilityMatrix.Core/Services/MetadataImportService.cs:182`, `ICivitApi.cs:16-17`). Update badges compare installed hashes to the model's latest version on CivitAI (`ModelIndexService.cs:713-813`).

### Launching

`RunPackage` (`ComfyUI.cs:625-685`) re-resolves the venv for the recorded Python version, applies the app's environment variables plus package-specific ones (ffmpeg on `PATH`, ROCm variables on Windows; `1231-1259`), strips `UV_BUILD_CONSTRAINT` so ComfyUI-Manager's own `uv pip install` does not break (`640-646`), runs the driver check, then starts `python -u main.py <args>` with `PYTHONUNBUFFERED=1` (`StabilityMatrix.Core/Python/PyVenvRunner.cs:522-612`). Readiness is detected by matching `To see the GUI go to http://host:port` in stdout (`ComfyUI.cs:674-683`), which also yields the URL the Inference client connects to. Launch arguments are declared per package as `LaunchOptionDefinition`s with hardware-derived initial values: `--lowvram` when the GPU memory level is low, `--cpu` when no NVIDIA or AMD GPU is seen, `--force-fp16` on macOS, `--disable-xformers` on non-NVIDIA, `--enable-manager` on (`ComfyUI.cs:269-387`). Stopping is `Process.Kill(entireProcessTree: true)` (`PyVenvRunner.cs:653-676`); on Windows every child is also put in a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` so nothing outlives the app (`StabilityMatrix.Core/Helper/ProcessTracker.cs:12-60, 184-260`).

## 4. What MAID can learn

Each item names where it would land in MAID. None of them needs the network.

1. **Shared model layout as data, and a MAID-owned block in `extra_model_paths.yaml`.** MAID's `vendor/comfyui.sh` writes five keys once and then never touches the file (`MAID/vendor/comfyui.sh`, the `[ ! -f extra_model_paths.yaml ]` guard in `wire`). SM's version is a declared layout (category to config key) rendered into a namespaced root key and regenerated idempotently while other keys are preserved. For MAID: keep a `models` map in `vendor/manifest.json` (category to subfolder under `models_dir`), have `wire` rewrite only the `maid:` root key of `extra_model_paths.yaml` on every run, and cover the categories ComfyUI actually reads (checkpoints, diffusion_models, loras, text_encoders, vae, clip_vision, embeddings, controlnet, upscale_models, style_models, model_patches). Adopted installs keep their other root keys.

2. **Unlink discipline.** SM removes only links it created and refuses a link that would sit inside its own target (`SharedFolders.cs:80-98, 189-225`). `maid vendor unlink` already deletes nothing; the cycle check is worth adding to `wire` for the `user/default/workflows` and `example_workflows` links, since SM shipped a bug where a looped workflow link recursed thousands of levels (v2.16.4 notes).

3. **Install state that reads the venv.** `maid vendor` reports pinned ref and installed/linked/missing. SM additionally knows the venv's Python and torch build. Add to `maid vendor`: the interpreter version from `.venv/pyvenv.cfg`, `torch <version>+<index>` from `uv pip show torch` (SM parses the `+cu130` suffix, `BaseGitPackage.cs:915-921`), and drift between `git rev-parse HEAD` of the checkout and the manifest `ref`. All local.

4. **Driver-versus-torch check before launch.** SM aborts a launch when torch is `+cu130` and `nvidia-smi` reports a driver below 580 (`BaseGitPackage.cs:887-950`). MAID pins cu130 in `vendor/comfyui.sh`; `maid doctor` and `maid up comfyui` should make the same check locally. This is the concrete "health beyond port open" item on the roadmap (section 7 of `MAID/docs/roadmap.md`).

5. **Launch options as declared defaults with hardware-derived initial values.** SM's `LaunchOptionDefinition` list sets `--lowvram` from GPU memory, `--cpu` when no GPU is seen, `--force-fp16` on macOS (`ComfyUI.cs:269-387`). MAID's `services/comfyui.json` is a fixed argv. An `options` block per service (documented flags, default on or off, and a `fixed` list for the privacy arguments `--disable-api-nodes --disable-auto-launch --listen 127.0.0.1` that no option may remove) would let `maid up comfyui --lowvram` exist without a second service file.

6. **Readiness from output, not only from the port.** SM matches `To see the GUI go to http://...` (`ComfyUI.cs:674-683`) and gets the real URL. MAID polls the port (`MAID/core/src/service.cpp`, `connect` at line 110). An optional `ready_pattern` in `services/*.json`, checked alongside the port, would work for ComfyUI, `llama-server` and Ollama and would catch a server that bound the port but is still loading a model.

7. **Windows, concretely (for the "Windows" note in `MAID/docs/vendor.md` and section 8 of the roadmap).** SM's Windows path is a checklist of what MAID will hit: NTFS junctions for directory links so no privilege or Developer Mode is needed (`Junction.cs`); Job Objects with kill-on-close so the service tree dies with the manager (`ProcessTracker.cs:26`), which is the design already named in the roadmap; a portable git prepended to `PATH` and exported as `GIT` for pip's VCS installs (`PyVenvRunner.cs:563-579`); `PYTHONUNBUFFERED=1` and `python -u` for live console output; the VC++ 2015-2022 redistributable as a prerequisite for torch (`WindowsPrerequisiteHelper.cs:34-39`); uv's interpreter store and cache pinned under the app's tree with `UV_PYTHON_INSTALL_DIR` and `UV_CACHE_DIR` so `%LOCALAPPDATA%` stays clean; and `cu126` for GPUs below compute capability 7.5. 

8. **Model sidecars and a local model index.** SM's `.cm-info.json` plus `.preview.<ext>` next to each file and a BLAKE3/SHA-256 index. Without any CivitAI lookup, `maid artifacts` could list `models/<category>` with counts and sizes, and `maid artifacts comfyui/outputs` could show the prompt from the PNG `prompt` and `parameters` chunks (`ImageMetadata.cs:110-118`). Hashing is useful on its own for de-duplication across the external drive.

9. **Adopt detection from the git remote.** SM's import dialog identifies a folder by reading `origin` from `.git/config` (`ViewModels/Dialogs/PackageImportViewModel.cs:347-361`). `maid vendor adopt comfyui PATH` checks for `main.py` (`MAID/core/src/vendor.cpp:147-149`); it could also confirm the remote is a ComfyUI fork and print the checked-out ref against the manifest.

10. **Missing custom nodes from a saved workflow, offline.** Workflow JSON carries `cnr_id` and `aux_id` per node (`WorkflowNodeAnalyzer.cs:8, 31-33`). A `maid artifacts comfyui/workflows` check could list packs a workflow needs that are not in `custom_nodes/`, with no registry query; installing stays a manual, pinned addition to `vendor/manifest.json`.

11. **Build constraints for old custom nodes.** SM pins `setuptools<82` for source builds via `UV_BUILD_CONSTRAINT` and `PIP_CONSTRAINT` (`BaseGitPackage.cs:256-266`). If a vendored custom node ever fails to build under uv, this is the fix, and it belongs in `vendor/comfyui.sh` next to the `custom_nodes/*/requirements.txt` loop.

12. **The Inference client, as a reference for ComfyUI's API surface.** `StabilityMatrix.Core/Inference/ComfyClient.cs` is a complete client (`POST /prompt`, `/interrupt`, `/upload/image`, `GET /history/{id}`, `/view`, `/object_info`, websocket `/ws?clientId=`) and `docs/advanced/comfyui-integration.md` documents it plainly. MAID has no GUI and should not build one, but if a future MAID tool drives ComfyUI directly (the roadmap's tool spokes), those are the endpoints and the event kinds to expect.

## 5. What MAID should not copy

- **Crash reporting and analytics.** Sentry on by default with full tracing and no settings toggle, a consent dialog whose default is "Share", daily launch pings. All of it is against `MAID/docs/cleanroom.md` and the harness's no-internet rule.
- **Update and notification polling.** Hourly manifest checks and a server-pushed notification feed on every launch. MAID updates by editing `vendor/manifest.json` and running `maid vendor add`, and that stays.
- **Tracking branch heads.** SM's default for many packages is "latest commit on main" with `pull --rebase --autostash`. MAID pins tags or commits and nothing tracks a head; `maid vendor` must keep refusing to move without a manifest change.
- **Auto-installing and enabling ComfyUI-Manager.** It puts a registry client inside ComfyUI. MAID's `services/comfyui.json` does not pass `--enable-manager`, and in ComfyUI v0.38 the flag is off unless given (`comfy/cli_args.py:161` in the ComfyUI checkout). Keep it that way.
- **Moving user files during link setup.** SM relocates a package's existing `models/*` into the shared library when it creates a link (`SharedFolders.cs:119-136`). MAID's wiring only creates links and copies workflows with `cp -an`; keep "never move what MAID did not create".
- **Unverified tool downloads and spoofed browser headers.** uv, git, Node and .NET are fetched without a checksum in the code shown; the tRPC client pretends to be the CivitAI website. MAID's `vendor/ollama.sh` verifies sha256 against the published file and aborts on mismatch; every release download MAID adds must do the same, and MAID never talks to a site's private endpoints.
- **Accounts, proxies and third-party AI.** Lykos login, the discovery proxy, Prompt Amplifier, Gemini. None of these belongs in a local-first CLI.
- **A GUI package manager.** Thirty package classes in C# is the wrong altitude for MAID. The manifest plus a shell script per service is the right one, and the ideas above all fit that shape.
- **Junctions as the only Windows link type for everything.** Junctions are for directories on local volumes; MAID's `cli-history` and `current` links are file and directory symlinks. On Windows, use junctions for directory links and plain copies or a config value for files, rather than requiring symlink privilege.

## 6. Recommendation

**(a) Nothing to run. Design ideas only.** The binary phones home at launch through channels with no settings toggle, and the app wants to own ComfyUI's launch, `extra_model_paths.yaml` and workflow folder, which would fight `maid vendor` and `services/comfyui.json`. The source is AGPL-3.0, so no code moves. The ideas in section 4 all land in `vendor/manifest.json`, `vendor/comfyui.sh`, `services/*.json`, `core/src/vendor.cpp` and `core/src/service.cpp`.

Roadmap items, ready to paste into `MAID/docs/roadmap.md` under "7. Services" and "8. Windows":

* **Regenerated model paths**: `vendor/manifest.json` gains a `models` map (ComfyUI category to subfolder under `models_dir`); `vendor/comfyui.sh wire` rewrites only the `maid:` root key of `extra_model_paths.yaml` on every run and leaves other keys as they are, so adopted installs keep their own entries. Cover every category ComfyUI reads, not just the five written today.
* **`maid vendor` reads the venv**: show the interpreter version from `.venv/pyvenv.cfg`, `torch <version>+<index>` from `uv pip show torch`, and whether the checkout's `HEAD` matches the manifest `ref`. No network.
* **Pre-launch driver check**: `maid doctor` and `maid up comfyui` compare the venv's torch CUDA suffix (`+cu130`) to the `nvidia-smi` driver version and refuse to start below the minimum (580 for cu130), with the fix named in the message.
* **Service options**: an `options` block in `services/*.json` (flag, default, description) rendered into the command, overridable as `maid up NAME --flag`; a `fixed` list holds the privacy arguments (`--disable-api-nodes`, `--disable-auto-launch`, `--listen 127.0.0.1`, `OLLAMA_NO_CLOUD`) that no option can remove.
* **`ready_pattern` in `services/*.json`**: a regex matched against the service's output in addition to the port check; when it captures a URL, `maid status` shows it. Covers ComfyUI ("To see the GUI go to"), llama-server and Ollama.
* **Link cycle guard**: `wire` refuses to create any symlink whose target contains the link path, and `maid vendor` reports such a link if it finds one.
* **Artifacts: models and outputs**: `maid artifacts` lists `models/<category>` from `models_dir` with counts and sizes, and shows the prompt embedded in a ComfyUI output PNG (`prompt` and `parameters` text chunks) for `comfyui/outputs`.
* **Workflow node check**: `maid artifacts comfyui/workflows --check` lists the node packs a saved workflow names in its `cnr_id` / `aux_id` properties that are not present in `custom_nodes/`. Reporting only; installing stays a manifest change.
* **Adopt verification**: `maid vendor adopt comfyui PATH` reads `origin` from `.git/config`, warns if it is not a ComfyUI repository, and prints the checked-out ref against the manifest.
* **Windows service manager**: Job Objects with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` for every service tree (already named in section 8), directory junctions for the vendor and artifact links, a portable git on `PATH` and in `GIT` for the ComfyUI venv, `PYTHONUNBUFFERED=1` for live logs, and a `maid doctor` check for the VC++ redistributable before torch is installed.
* **Windows Python isolation**: `UV_PYTHON_INSTALL_DIR` and `UV_CACHE_DIR` under `%LOCALAPPDATA%\maid\` so uv writes nothing else into the profile; `cu126` instead of `cu130` when the GPU's compute capability is below 7.5.
